# 午夜学院：先机制、后关卡的探索记录

本文件负责核心机制候选、规则推演、边界和淘汰依据。续写时记录同一套规则产生的新现象与反例，明确哪些已验证；关卡与完整体验收敛后更新 `NIGHT_SCHOOL_PROTOCOL_DESIGN.md`，经过写入 `../log.md`。

状态：2026-10-12 的机制探索草案。目前没有游戏实现，也没有经过试玩验证的主机制。

## 1. 本轮设计顺序

用户提出先设计机制，再根据机制设计关卡，借鉴系统型解谜的设计方法，保持玩法原创。

采用以下顺序：

1. 提出能够在一句话内理解的少量基础规则。
2. 用纸面状态表或极小实验推演规则，包括组合、边界和反直觉结果。
3. 检查是否存在多种不同的、有意义的推理现象。
4. 核对机制与真实知识的对应关系，解释抽象与原创魔法设定。
5. 根据玩家需要发现的现象设计关卡，逐步组织教学与挑战。
6. 最后整合午夜学院叙事、知识名称、建筑表现和纸灵编程体验。

规则和知识的对应关系应在构思阶段持续核对。可以后确定术语与叙事包装，但不能先定一套无关玩法，再靠名称宣称它体现某个知识规律。

当前合并稿中的三关改为教学与调试的候选例子；不再先锁定它们，再为每关添加独立机关。纸灵、规则编辑器和透镜也作为玩法的载体，主机制需要单独验证。

## 3. 首个候选：持续跟随与一次记住

一句话：一个装置既可以跟随另一个对象的当前状态，也可以保存那个对象在某一时刻的状态。

候选知识对应：状态读取、值的快照、实时依赖与有向数据流。魔法命名暂不锁定；可先使用清楚的“跟随”和“记住”。

### 3.1 最少的规则

1. 世界中的指定对象输出一个可观察的布尔状态。例如压力台被占据时为真，离开后为假。
2. **跟随**：目标输入保存一个有效来源。每次读取时取得来源当前的值；来源变化，目标按世界更新规则响应。
3. **记住**：施法时读取来源当前的值，将该值存为目标输入的快照。之后来源变化，不改变这份快照。
4. 目标装置根据输入值响应。例如桥的输入为真时接通，为假时断开。

两种操作可以重新设置同一个兼容目标输入。记录的值、依赖来源与目标反应都由透镜呈现；玩家不能直接指定一个与来源无关的任意值。

这是一种读取与依赖的游戏抽象。“跟随”没有定义双向写入，不应直接称作完整的可写指针或所有编程语言中的引用语义。

### 3.2 状态表

| 情况 | 来源当前值 | 跟随输入读到的值 | 在来源为真时记住的快照 |
| --- | --- | --- | --- |
| 站在压力台上 | 真 | 真 | 真 |
| 离开压力台 | 假 | 假 | 真 |
| 再次站回压力台 | 真 | 真 | 真 |

表中的差异来自同一条规则：跟随读取当前状态，快照保存取样时的值。

### 3.3 一个用于检查机制的情境

压力台与远处的桥相连。纸灵站在压力台上时桥接通，但必须先离开压力台，经过一段道路才能到桥。

- 如果桥持续跟随压力台，纸灵离开后桥断开。
- 如果纸灵在站台时让桥记住台的状态，离开后桥仍接通。
- 如果在离开之后取样，桥会记住假；需要重新理解取样时机或重新设置来源。

这只是机制推演情境，尚未形成完整关卡。行走布局、魔法作用范围和可用程序条件需要后续一起验证。

## 4. 同一规则可能产生的不同现象

每一个现象都应先在相同语义下验证，再考虑能否成为关卡。

| 现象 | 玩家需要理解的关系 | 潜在推理价值 |
| --- | --- | --- |
| 当前与过去分离 | 来源改变，快照保持 | 操作时机影响之后的世界状态 |
| 同源装置分化 | 两个目标跟随同源，其中一个改为快照 | 找到需要切断或保留的依赖 |
| 来源重新绑定 | 跟随改到另一来源，旧来源不再控制该输入 | 改变因果关系，同时追踪影响范围 |
| 依赖链 | A 影响 B，B 再影响 C | 看清间接影响以及快照会在哪一处截断传播 |
| 已知规则的反例 | 快照可能保存不希望保持的状态 | 机制同时带来解决办法和新问题 |
| 程序控制取样时机 | 条件决定何时记住，状态变化后执行其他操作 | 知识与纸灵行为直接结合 |

不能因为状态表能成立就宣称这些都会有趣。若实际谜题全部退化为“等灯亮了，再按记住”，应重新设计或淘汰这套机制，而不是靠加长路径增加难度。

## 5. 怎样接回两份原始构思

### 透镜、操作与关系

- **Lens**：显示来源的当前值、目标是跟随还是快照、信号的传递方向。
- **Operator**：设置跟随，或对来源进行取样并记住当前值。
- **Relation**：跟随产生持久的读取依赖；取样把该输入改成独立快照。

玩家在场景内先观察和试验，随后可以让纸灵执行同样的操作。手动试验与正式运行依然共用同一语义。

### 纸灵程序

一种仅供讨论的程序形式是：

```text
脚下有压力台，且桥还未保存状态 → 让桥记住当前压力台的状态
前方道路可通行                 → 前进
```

候选程序仍按第一匹配优先级执行。取样是一个完整行动；下一步重新判断，因此需要能表达“已经记住”的条件，避免一直在同一位置反复取样。

这里新的解谜决策来自何时保留状态、保留哪个来源、保留多久以及哪些装置需要继续跟随。程序排序负责把这套决策实现为可观察的行为。

## 6. 边界必须先明确

为了让玩家能推理，以下问题应在机制实验阶段确定：

- 每次操作的有效来源与目标在哪里，是否需要同房间、可见或指定端口范围？
- 来源值先更新，还是纸灵先执行？初版建议在行动前读当前状态，行动后统一更新世界。
- 跟随链怎样传播？初版可使用无环关系图，按依赖顺序求值。
- 目标自身有没有状态输出？如果有，应区分输入值、装置状态和输出值。
- 快照保存至何时？候选是持续到重新设置或重试，不增加隐藏倒计时。
- 无来源、类型不兼容、循环连接怎样反馈？应明确显示无效原因，不静默采用猜测值。
- 桥变化时纸灵已经站在桥上怎么办？需要统一的占用规则；不能为某一关临时修改。
- 重试恢复哪些设置与快照？布置和正式运行应有可重复的起点。

这些都是待确定的规则边界。任何改变都需要重新检查已有推演与关卡，避免在规则之外堆补丁。

## 7. 机制实验的判断标准

先做没有正式故事与精美素材的规则实验，目标是回答：

1. 玩家能否在很短的试验中说清跟随与快照的差别？
2. 同一机制是否产生至少三种不同的推理现象，包含一个反直觉但可解释的结果？
3. 玩家是否需要重新理解关系或时机，而不只是重复相同操作？
4. 规则能否跨布局复用，且不会因为关卡不同而偷偷改变？
5. 是否存在难以看见的状态、繁琐操作或大量特例？
6. 程序执行与直接试验是否一致？
7. 机制与知识能否准确对应？去掉魔法名字后，知识关系仍然可观察。

当前没有完成这些实验。纸面推演的作用是尽早发现问题，不代替玩家体验验证。

## 8. 机制通过后再生成关卡

将每个已验证的现象转换成一个关卡想让玩家发现的事实：

```text
发现当前与快照的差异
    ↓
发现取样时机改变后果
    ↓
发现切断依赖能让同源目标分化
    ↓
在组合布局中自行选择来源、依赖与程序
```

每关尽量用最小布局突出一个新发现，之后用变式验证玩家真的理解。复杂关卡可以结合之前的现象，但不靠无关规则或大量移动步数增加负担。

先保留多种合法尝试，再根据目标状态判断成功。参考程序用于设计核验，不用于匹配玩家答案。
