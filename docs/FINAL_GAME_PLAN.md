## 1. 定位

- 选题：The Midnight Academy。
- 名称：《夜校协议》。
- 形式：网页编程解谜，原创纸灵与纸页庭院。
- 核心：指令可以作为世界中的数据；运行程序会交换、取得和留下指令。
- 当前规模：一个纸灵、三个动作、三槽循环程序、三个小关卡。

玩家编排起始程序，然后观察纸灵执行。地面的符文换进程序后会成为行动；被换出的指令留在世界，仍能再次取回。世界与程序使用同一种表示，操作的结果能够继续作为操作。

## 2. 一句话机制

**交换脚下符文与下一格程序；地面符文进入程序后，才会执行。**

| 指令 | 稳定规则 |
| --- | --- |
| 前进 | 按纸灵当前朝向移动一个地面格 |
| 右转 | 原地顺时针转四分之一圈 |
| 交换 | 对调脚下符文和下一槽位的程序指令 |

地面存放的也只有这三种符号。地面不会自动触发行动。

## 3. 执行语义

1. 所有关卡使用三个程序槽位，起始执行第一槽。
2. 每拍只执行当前槽位的一个行动，然后移到下一槽。第三槽之后回到第一槽。
3. 交换读取动作前的两个内容，并同时对调。位置、朝向不变；下一拍执行新指令。
4. 第三槽执行交换时，目标是第一槽。
5. 交换符号本身没有特殊待遇：可以进入程序，也可以留在地面；换进程序后正常执行。
6. 程序与地面合计的每种符号数量在运行中守恒。编辑起始程序属于新一轮设置。
7. 前方无地面时停止，不自动绕路，也不自动改变朝向。
8. 抵达明确显示的出口即成功，不匹配参考程序，不检查未公开的交换次数或收集标记。
9. 完整循环检测包含位置、朝向、执行槽位、程序和全部地面内容；仅回到同一个位置不代表重复。
10. 运行到 256 拍仍未完成时停止。该预算用于结束无果试验；当前参考轨迹远低于预算。

这是有限的指令与数据交换模型，不宣称实现完整计算机体系结构或无限递归空间。

## 4. 操控与反馈

- 点击程序格，恢复起点后选择前进、右转或交换；保留其他起始槽位。
- 运行 / 暂停、一步、撤回、重来。运行期间不能改写程序。
- 展示实际运行中的程序；与起始不同的槽位标出原来指令，起始程序另行显示。
- 交换时地面与收到指令的程序格同时闪动。展示刚交换的两处；其他时候展示假如现在交换的对象。
- 改写过的地面有虚线与记号；点击地面可查看当前符文和原来内容。
- 撤回恢复位置、朝向、执行槽位、程序、地面、状态与执行记录。
- 重来恢复世界初值和本轮起始程序；清空改动恢复本关默认程序。
- 起始程序与完成章节保存在浏览器，未完成的运行现场不自动保存。
- 首次进入显示目标、三种动作和交换关系；关卡不自动填入答案。提示由玩家主动打开。

所有移动由程序完成。点击地面用于观察，不直接移动纸灵或改写符文。

## 5. 由机制形成的三关

关卡采用统一规则，当前场景为 3 列 × 4 行地面。横向向东、纵向向南；起点 `(0,0)` 朝东，出口 `(2,3)`。

| 关卡 | 要发现的现象 | 已验证的参考轨迹 |
| --- | --- | --- |
| 借一个转弯 | 起始程序没有右转，也能从地面取得右转并执行 | 前进、前进、交换，8 拍；另有三种合法起始程序 |
| 把交换带走 | 换来的交换立即执行，继续改变程序 | 前进、右转、交换，16 拍 |
| 回来取走它 | 回到曾修改的地面，取回之前留下的交换指令 | 前进、交换、前进，28 拍 |

第二关不接受原样沿用第一关参考程序的轨迹；第三关也不能原样沿用前两关参考程序。通过符文布局与执行顺序形成这些差异，判胜函数没有关卡专用规则。

在公开三槽字母表、256 拍预算下枚举全部 27 种初始程序：三关分别发现 4、1、1 个成功程序。后两关的当前布局只有一个成功起始排列，但实际执行会取得、留下和再次执行不同指令。多解数量与趣味是不同的评估维度。

## 6. 知识与参赛表达

知识内容包括：指令与数据共享表示、顺序与循环执行、运行时修改程序、有限状态、符号守恒和完整状态调试。午夜学院的符文承担实际运行关系。

演示从一个最初不会转弯的程序出发，观察地面右转进入程序、下一拍真的执行，再撤回观察两边恢复。第二段展示交换指令作用于交换指令；第三段展示世界保留先前操作，回访时程序发生新的变化。

借鉴系统型解谜的少量规则、组合后果和机制探索方法；角色、界面与关卡保持原创。相关作品差异、试玩数据和最终比赛提交材料仍需单独整理。

## 7. 当前边界与验证

核心引擎、三关、指令选择、运行调试、完整撤回、状态呈现和本地保存已实现。25 项检查覆盖参考与失败程序、取用指令、操作作用于操作、回收之前留下的指令、符号守恒、循环与预算、撤回和不同合法解。

地形拓扑固定，当前没有房间搬运、嵌套空间、多角色、条件语言、自由代码输入、音效或独立世界编辑器。旧版跟随、记忆和 WHEN→DO 不属于第二版。

逻辑与 UI 检查不等于机制趣味通过。需新玩家试玩评估是否看懂交换、自行发现新用途、理解失败，以及第三关是否出现有意义的回访规划。运行步数不作为体验时长或难度证据。
