# 工程维护入口

本文记录当前模块职责、兼容约定和检查方式。功能与验收范围看 README 和对应状态文档，历史经过留在 `log.md`。

## 项目与版本

`von-neumann-dreams/` 是完整项目根目录。修改前先核对 `git status`、当前分支与上游差距；`fetch` 只更新远程记录，不会自动更新本地文件。先保存已有工作，再同步并确定实现基线。

网页已有独立十三关和三套旧五关。开发网页默认旧课程，`?version=v2` 或选馆菜单进入十三关；单文件可按构建参数默认进入十三关。实现、试玩反馈与验收边界见 [V2_DEMO_STATUS.md](V2_DEMO_STATUS.md)。Godot 原型独立记录在 [NATIVE_DEMO_STATUS.md](NATIVE_DEMO_STATUS.md)，网页检查不计入原生验收。

## 模块职责

| 位置 | 职责与边界 |
| --- | --- |
| `web/level-catalog.js` | 四套关卡的数组、URL 身份、存储键及通关格式兼容；保留现有公开入口 |
| `web/levels-v2.js`、旧关卡文件 | 地图、机关、接线、目标与提示；新关不覆盖旧关 |
| `web/level-validation.js` | 新配置、引用、光学和跨世界接线校验 |
| `web/engine.js`、`entities.js` | 动作、实体、碰撞、支撑、恢复与判胜；规则先提交，动画不决定结果 |
| `web/science.js` | 电路求值与真实光路；界面、规则和渲染共用结果 |
| `web/app.js` | 输入、切关、弹窗与交互编排；切关取消旧寻路，流程使用当前关卡集长度 |
| `web/course-ui.js` | 电路面板、札记表格及欢迎状态；不自行解析札记存档 |
| `web/notebook.js` | 新旧札记校验、内存记录与持久化；不参与开门、支撑或判胜 |
| `web/renderer.js`、`surface-markings.js`、`world-labels.js`、`motion.js` | 场景、复用的贴面标记、竖直世界浮字/气泡与动作呈现；保留减少动态模式，不复制玩法状态机 |
| `scripts/`、`tests/` | 预览、构建与回归；复用现有 Node 测试入口，不为流程形式增加依赖 |

数据流为：目录选择配置 → 创建状态 → `Game.act` 更新规则 → 界面与场景呈现。札记只保存已经观察的结果，撤销机关不抹掉发现，札记也不锁存真实电路输出。

## 存储契约

- 各关卡集使用目录中定义的独立键；旧通关继续存稳定 ID 数组，2.0 保留 `{format:1,catalog:'v2',completed:[...]}`。
- 旧札记为关卡 ID → 输入位串 → `{gate,door,front?}`，早期布尔记录继续可读；2.0 保留 `{format:1,catalog:'v2',levels:{...}}`，关内再按电路 ID 和输入位串分组。
- 只接收已配置的关卡、电路、正确输入位数和布尔节点结果。损坏 JSON、数组、空行、缺失节点和未知封装不算已观察，其他合法记录继续保留；读取不主动写回。
- 只有观察变化时写入，避免每次渲染重复保存。访问被拒或配额不足时，本次内存记录仍可用；刷新后的保留取决于实际写入结果。
- 清除经过现有确认弹窗，只处理当前版本的通关、札记与欢迎状态，不调用 `localStorage.clear()`。返回第一关后，初始可见输入会重新记录。
- 十三关欢迎键与旧版独立；旧课程继续沿用原有共享欢迎键。关内状态快照仍由引擎负责。

## 运行与检查

需要 Node.js 20+ 和 npm，在项目根目录运行：

```bash
npm ci
npm run dev
npm run check
# 导出默认直达十三关的单文件
npm run build -- --default-version=v2
```

`check` 顺序执行 `npm test`、`npm run verify:puzzles`、`npm run verify:v2`、`npm run build`。自动检查覆盖旧关、十三关规则、恢复、动效、存档与特殊路径构建；涉及界面或存储时，另用隔离浏览器检查新旧切换、札记、刷新、清除确认和窄屏，不使用用户真实进度做清除测试。

测试后关闭本次启动的预览和浏览器。构建产物、依赖与临时检查进入现有忽略目录；源码历史使用 Git，不复制 old、backup、final 等版本。当前历史设计稿、来源快照和 Demo 文档各有职责，整理前确认出处、引用和对应版本。
